Cycle 1: Writing Your Own Functions

Why Write Functions?

Three clinics, three copies of the same line:

clinic_a$bmi <- clinic_a$weight / clinic_a$height^2
clinic_b$bmi <- clinic_b$weight / clinic_b$height^2
clinic_c$bmi <- clinic_c$weight / clinic_a$height^2   # spot the bug?
  • Copy-paste multiplies bugs: the third line silently uses clinic A’s heights.
  • Rule of three: once you have copied code twice, write a function.
  • A function gives an idea one name, one place to fix, one place to test.

Anatomy of a Function

bmi <- function(weight_kg, height_m) {
  weight_kg / height_m^2
}

bmi(70, 1.75)
[1] 22.85714
  • Name: bmi (a verb or noun that says what it computes).
  • Arguments: weight_kg, height_m (the inputs).
  • Body: the code inside { }.
  • The value of the last expression is returned.

Functions Are Vectorized for Free

If the body uses vectorized operations, so does your function:

weights <- c(55, 70, 92)
heights <- c(1.60, 1.75, 1.80)

bmi(weights, heights)
[1] 21.48437 22.85714 28.39506
  • One call handles one patient or a thousand.
  • Week 8’s ifelse() and case_when() work inside functions the same way.

Functions Inside mutate()

A vectorized function drops straight into mutate():

library(dplyr)
library(r02pro)   # the gm data
tibble(id = 1:3, weight = weights, height = heights) |>
  mutate(bmi = bmi(weight, height))
# A tibble: 3 × 4
     id weight height   bmi
  <int>  <dbl>  <dbl> <dbl>
1     1     55   1.6   21.5
2     2     70   1.75  22.9
3     3     92   1.8   28.4

Functions Can Use Last Week’s Tools

bmi_category <- function(bmi_value) {
  case_when(
    bmi_value < 18.5 ~ "underweight",
    bmi_value < 25   ~ "healthy",
    bmi_value < 30   ~ "overweight",
    bmi_value >= 30  ~ "obese"
  )
}

bmi_category(c(17.2, 22.9, 28.4, 31.0, NA))
[1] "underweight" "healthy"     "overweight"  "obese"       NA
  • No catch-all TRUE ~ ... line, so a missing BMI stays NA instead of becoming "obese".
  • Small functions compose: bmi_category(bmi(weights, heights)).

Early Exits with return()

safe_ratio <- function(num, den) {
  if (den == 0) {
    return(NA)
  }
  num / den
}

safe_ratio(10, 4)
[1] 2.5
safe_ratio(10, 0)
[1] NA
  • return() stops the function immediately: use it for early exits.
  • Otherwise let the last line be the result (the tidyverse style).

Cycle 2: Arguments, Scoping & Safety

Default Arguments

rate_per <- function(cases, population, per = 100000) {
  cases / population * per
}

rate_per(250, 1200000)              # uses the default: per 100,000
[1] 20.83333
rate_per(250, 1200000, per = 1000)  # override: per 1,000
[1] 0.2083333
  • Put arguments with defaults last: the common case needs no typing.
  • Name optional arguments when you override them (per = 1000).

Argument Matching

rate_per(population = 1200000, cases = 250)   # named: any order works
[1] 20.83333
rate_per(1200000, 250)                          # positional: order matters!
[1] 4.8e+08
  • Convention: pass the first one or two data arguments by position, everything else by name.
  • The second call is a silent bug: cases and population are swapped.

Scoping: What Can a Function See?

Reaching outside (fragile)

threshold <- 140

flag_high <- function(sbp) {
  sbp >= threshold   # not an argument!
}

flag_high(c(120, 135, 150))
[1] FALSE FALSE  TRUE
threshold <- 130     # someone edits a global...
flag_high(c(120, 135, 150))
[1] FALSE  TRUE  TRUE

Passing it in (robust)

flag_high <- function(sbp, threshold = 140) {
  sbp >= threshold
}

flag_high(c(120, 135, 150))
[1] FALSE FALSE  TRUE
flag_high(c(120, 135, 150), threshold = 130)
[1] FALSE  TRUE  TRUE

R looks for a name inside the function first, then in the environment where the function was defined.

What Happens Inside Stays Inside

total <- 0

add_cases <- function(new_cases) {
  total <- total + new_cases   # creates a LOCAL copy of total
  total
}

add_cases(25)
[1] 25
total
[1] 0
  • Assignment inside a function never changes the global object.
  • To keep a result, return it and assign it: total <- add_cases(25).

Defensive Programming: stopifnot()

rate_per <- function(cases, population, per = 100000) {
  stopifnot(is.numeric(cases), is.numeric(population), all(population > 0))
  cases / population * per
}

rate_per(250, 0)
Error in `rate_per()`:
! all(population > 0) is not TRUE
rate_per("250", 1200000)
Error in `rate_per()`:
! is.numeric(cases) is not TRUE
  • Check inputs at the top of the function, before any work happens.
  • Conditions are checked in order: the first one that is not all TRUE stops the function with an error.

Custom Error Messages with stop()

bmi <- function(weight_kg, height_m) {
  if (any(height_m > 3, na.rm = TRUE)) {
    stop("height_m looks like centimeters; divide by 100 first")
  }
  weight_kg / height_m^2
}

bmi(70, 175)
Error in `bmi()`:
! height_m looks like centimeters; divide by 100 first

Tip

A loud error that says how to fix it beats a silent BMI of 0.0023 that flows into your paper.

Cycle 3: Iteration without Loops: purrr

From for Loop to map()

clinic_sbp <- list(
  brooklyn = c(128, 141, 135, 152),
  queens   = c(118, 122, 139),
  bronx    = c(145, 160, 138, 149, 151)
)

Week 8 style

clinic_means <- numeric(length(clinic_sbp))
for (i in seq_along(clinic_sbp)) {
  clinic_means[i] <- mean(clinic_sbp[[i]])
}
clinic_means
[1] 139.0000 126.3333 148.6000

purrr style

library(purrr)

map(clinic_sbp, mean)
$brooklyn
[1] 139

$queens
[1] 126.3333

$bronx
[1] 148.6

map() Always Returns a List

map(.x, .f) applies .f to each element of .x:

  • Output has the same length as the input.
  • Output keeps the input’s names.
  • No pre-allocation, no index, no off-by-one bugs.

When each result is a single value, a typed variant returns a vector instead of a list.

Typed Variants: map_dbl(), map_int(), map_lgl(), map_chr()

map_dbl(clinic_sbp, mean)
brooklyn   queens    bronx 
139.0000 126.3333 148.6000 
map_int(clinic_sbp, length)
brooklyn   queens    bronx 
       4        3        5

The suffix is a promise about the output type, and purrr enforces it:

map_dbl(clinic_sbp, range)   # range() returns TWO numbers per clinic
Error in `map_dbl()`:
ℹ In index: 1.
ℹ With name: brooklyn.
Caused by error:
! Result must be length 1, not 2.

Anonymous Functions

For one-off logic, write the function right inside map():

map_dbl(clinic_sbp, \(x) mean(x >= 140))   # share of readings >= 140
brooklyn   queens    bronx 
     0.5      0.0      0.8 
map_lgl(clinic_sbp, \(x) any(x >= 160))     # any reading >= 160?
brooklyn   queens    bronx 
   FALSE    FALSE     TRUE
  • \(x) ... is shorthand for function(x) ....
  • Older code (and many AI answers) write ~ mean(.x >= 140): same idea, older syntax.

A Data Frame Is a List of Columns

So map() over a data frame visits each column:

gm_2008 <- gm |>
  filter(year == 2008) |>
  select(life_expectancy, child_mortality, GDP_per_capita)

map_int(gm_2008, \(col) sum(is.na(col)))            # missing-data audit
life_expectancy child_mortality  GDP_per_capita 
             41              39              34 
map_dbl(gm_2008, \(col) median(col, na.rm = TRUE))
life_expectancy child_mortality  GDP_per_capita 
         72.100          20.900           5.125

Cycle 4: Integration + AI Corner

A Function That Returns a Table

summarize_continent <- function(data, ct, yr = 2008) {
  data |>
    filter(year == yr, continent == ct) |>
    summarize(
      continent   = ct,
      n_countries = n(),
      median_le   = median(life_expectancy, na.rm = TRUE)
    )
}

summarize_continent(gm, "Asia")
# A tibble: 1 × 3
  continent n_countries median_le
  <chr>           <int>     <dbl>
1 Asia               46      71.7

map() + list_rbind(): One Row per Group

Last week’s loop printed one line per continent. Now we get a table back:

continents <- c("Africa", "Americas", "Asia", "Europe", "Oceania")

map(continents, \(ct) summarize_continent(gm, ct)) |>
  list_rbind()
# A tibble: 5 × 3
  continent n_countries median_le
  <chr>           <int>     <dbl>
1 Africa             50      60.2
2 Americas           36      74.6
3 Asia               46      71.7
4 Europe             38      79.3
5 Oceania            12      65.8
  • list_rbind() stacks a list of data frames (older code uses map_dfr()).
  • group_by() + summarize() does this particular job too; map() shines when the per-group step is not a dplyr verb (one plot, one model, or one file per group).

Loop or map()?

Use a for / while loop when… Use map_*() when…
each step depends on the previous one (running totals, while) each element is handled independently
the point is a side effect (printing, saving files) the point is the returned values
you are fine pre-allocating output yourself you want output allocated and type-checked for you

Both are correct R; map() is usually shorter and harder to get wrong.

AI Corner: The Function That Only Works Here

Asked for “the share of countries with life expectancy at or above a cutoff,” an AI wrote:

df <- gm |> filter(year == 2008)

share_above_ai <- function(cutoff) {
  mean(df$life_expectancy >= cutoff, na.rm = TRUE)
}

share_above_ai(75)
[1] 0.3230769

It runs, handles NA, and the number looks plausible. Ship it?

AI Corner: Auditing the Function

Audit findings:

  1. Reads df from the global environment. Reuse the name later and the same call silently gives a different answer:
df <- gm |> filter(year == 1990)
share_above_ai(75)
[1] 0.1897436
  1. Hard-wires life_expectancy: useless for any other variable.
  2. No check that cutoff is a single number.

AI Corner: The Audited Version

share_above <- function(x, cutoff) {
  stopifnot(is.numeric(x), is.numeric(cutoff),
            length(cutoff) == 1)
  mean(x >= cutoff, na.rm = TRUE)
}

le_2008 <- gm |>
  filter(year == 2008) |>
  pull(life_expectancy)

share_above(le_2008, 75)
[1] 0.3230769
map_dbl(c(60, 70, 80),
        \(k) share_above(le_2008, k))
[1] 0.8410256 0.5846154 0.1435897
  • The data arrives as an argument x, so the function works for any year and any variable.
  • stopifnot() rejects a bad cutoff before any work happens.
  • map_dbl() reuses it across cutoffs in one line.

Important

Everything a function uses should arrive through its arguments.
