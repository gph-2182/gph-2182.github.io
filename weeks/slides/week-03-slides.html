What is a Matrix?

A matrix is a 2-dimensional collection of elements of the same basic type (homogeneous), arranged in rows and columns.

Column-by-Column (Default)

m1 <- matrix(1:6, nrow = 2, ncol = 3)
m1
     [,1] [,2] [,3]
[1,]    1    3    5
[2,]    2    4    6

Row-by-Row (byrow = TRUE)

m2 <- matrix(1:6, nrow = 2, ncol = 3, byrow = TRUE)
m2
     [,1] [,2] [,3]
[1,]    1    2    3
[2,]    4    5    6

Dimensions & Naming

# Check matrix dimensions
dim(m2)    # returns c(number_of_rows, number_of_columns)
nrow(m2)   # 2 rows
ncol(m2)   # 3 columns

# Adding Row and Column Names
rownames(m2) <- c("Hospital_A", "Hospital_B")
colnames(m2) <- c("ICU_Beds", "Ventilators", "Nurses")
m2
           ICU_Beds Ventilators Nurses
Hospital_A        1           2      3
Hospital_B        4           5      6

2D Matrix Subsetting: [row, column]

Always remember: [row, column] (think “RC Cola” or “Roman Catholic”).

# 1. Single element: row 1, col 2
m2[1, 2]                     # 2

# 2. Entire row: leave column blank!
m2[1, ]                      # ICU_Beds: 1, Ventilators: 2, Nurses: 3

# 3. Entire column: leave row blank!
m2[, "ICU_Beds"]             # Hospital_A: 1, Hospital_B: 4

# 4. Submatrix: rows 1:2, columns 2:3
m2[1:2, 2:3]

# 5. Conditional replacement
m2[m2 < 3] <- 0

Cycle 2: Lists & Heterogeneous Data

Why Do We Need Lists?

Vectors and matrices are homogeneous (all elements must be the exact same type).

In public health and clinical research, real records contain heterogeneous data: * Patient ID (character) * Demographics (character, numeric) * Blood pressure readings across multiple visits (numeric vector of length 5) * Lab test results (logical or nested sub-records)

A list is a flexible container whose elements can be of any type, length, or structure!

Creating & Inspecting Lists

patient_record <- list(
  id = "PT-84920",
  age = 54,
  smoker = FALSE,
  sbp_history = c(138, 142, 130, 128, 135),
  metadata = list(clinic = "Bellevue", enrolled = "2026-01-15")
)

# Inspect structure
str(patient_record)
List of 5
 $ id         : chr "PT-84920"
 $ age        : num 54
 $ smoker     : logi FALSE
 $ sbp_history: num [1:5] 138 142 130 128 135
 $ metadata   :List of 2
  ..$ clinic  : chr "Bellevue"
  ..$ enrolled: chr "2026-01-15"

The Crucial Difference: $ vs [[ ]] vs [ ]

1. $ or [[ ]] (Extract Contents)

Extracts the raw object inside the list compartment:

# Returns a NUMERIC VECTOR
patient_record$sbp_history
patient_record[["sbp_history"]]

# Now you can do math!
mean(patient_record$sbp_history) # 134.6

2. [ ] (Sub-list / Slice)

Returns a smaller list containing that compartment:

# Returns a LIST of length 1
sub_list <- patient_record[4]
typeof(sub_list) # "list"

# mean(sub_list) WILL FAIL!
# Lists cannot be averaged directly.

Tip

Think of a list as a train with cargo cars. [4] gives you the 4th car; [[4]] opens the car and gives you the cargo inside!

Cycle 3: Data Frames & Tibbles

Data Frames: The Heart of Data Analysis

A data frame is a list of equal-length vectors. Each column is a variable; each row is an observation.

# Creating a data frame
cohort <- data.frame(
  id = c("P01", "P02", "P03", "P04", "P05"),
  age = c(45, 62, 38, 71, 55),
  bmi = c(24.2, 31.0, 27.5, 29.8, 22.1),
  diabetes = c(FALSE, TRUE, FALSE, TRUE, FALSE),
  stringsAsFactors = FALSE
)

# Inspecting
nrow(cohort)       # 5 observations
ncol(cohort)       # 4 variables
summary(cohort)    # Summary statistics for each column

Tibbles vs. Base Data Frames

A tibble (tibble::tibble()) is a modern data frame with refined behavior:

Base data.frame

  • Prints all rows and columns to console (can flood screen).
  • May coerce strings or drop dimensions unpredictably (df[, 1] becomes a vector).
  • Partial name matching (df$d might match df$diabetes).

tibble (library(tibble))

  • Clean printing: shows top 10 rows and variable types (<chr>, <dbl>, <lgl>).
  • Strict subsetting: tb[, 1] always stays a tibble.
  • Never coerces types or uses partial matching.

Subsetting & Filtering Data Frames

# 1. Accessing columns
cohort$bmi
cohort[["age"]]

# 2. Creating a new computed column
cohort$bmi_high <- cohort$bmi >= 30.0

# 3. Filtering rows by condition: df[condition, ]
seniors <- cohort[cohort$age >= 60, ]
seniors

# 4. Complex filtering: BMI > 25 AND non-diabetic
overweight_non_diab <- cohort[cohort$bmi > 25 & !cohort$diabetes, ]

Exporting Cleaned Datasets

Once your data is cleaned and validated, save it back to disk:

# Exporting to CSV
write_csv(cohort, "data/cleaned_cohort.csv")

# Saving R binary objects (.rds preserves exact data types!)
saveRDS(cohort, "data/cleaned_cohort.rds")
restored_cohort <- readRDS("data/cleaned_cohort.rds")

AI Corner: The Silent Import Bug

The “Unknown” String Trap

❌ What AI Generated

# Prompt: "Read this blood pressure dataset from CSV"
bp_df <- read.csv("bp_data.csv")
mean(bp_df$systolic)

Output: [1] NA

Why? In the CSV, row 42 contained "Unknown". Base read.csv converted the entire systolic column to character!

✅ The Verified Fix

Always specify explicit na strings upon import:

library(readr)
bp_df <- read_csv(
  "bp_data.csv",
  na = c("", "NA", "Unknown", "Refused", "-99")
)

# Verify column types
spec(bp_df)
mean(bp_df$systolic, na.rm = TRUE)
