Course Description

R is one of the most popular programming languages in statistics and data science. This course will introduce various R programming topics, including R objects, data visualization, data import & export, data manipulation, creating functions and iterations for statistical simulations, and writing high-quality reports with R Markdown. The course will focus on public health datasets as illustrations to best meet the practical needs of GPH students but is also open to those of other backgrounds. By the end of the course, students will be able to comfortably program in R for effective data preprocessing, analysis and presentation. This course does not require prior experience in programming or statistics and serves as a foundation for other courses in biostatistics, epidemiology, and data science.

Course Overview

This course equips graduate students with foundational and modern computing skills for reproducible public health data science. Using a dual-track pedagogical approach, students learn fundamental computational primitives alongside modern, expressive tidyverse workflows. The curriculum covers Quarto reproducible publishing, vectors, matrices, lists, data frames, publication-quality graphics with ggplot2, robust data wrangling with dplyr and tidyr, string and factor manipulation, functional programming with purrr, and Monte Carlo simulation. Students will also master responsible, ethical AI-assisted programming to accelerate learning, debugging, and code documentation while building genuine human fluency.

Course Format

This is a 3-credit in-person course, including 14 in-person class sessions (14 × 160 minutes = 2,240 minutes) and 10 minutes of individual final project consultation, totaling 2,250 minutes of instructional time.

Course Requirements and Expectations

  • Attendance (5%): Checked every session. Up to 2 excused absences per semester carry no penalty. To be excused, submit the Excused Absence Request form at least 60 minutes before the class start time; you will receive an automatic email with the outcome. Your first excused absence in a course needs no documentation; every further request must include documentation uploaded with the form. Requests inside the 60-minute window or after class are not excused unless it was a genuine emergency and documentation is uploaded with the form; the instructor reviews those case by case.
  • In-Class Paired Exercises (10%): Active paired programming in every session. Graded for completeness and effort (not strict correctness). Lowest 2 scores dropped.
  • Weekly Exercises (35%): 12 autograded assignments submitted via GitHub. Immediate automated feedback upon push. Lowest 2 scores dropped. Late: 20% within 24h, 40% within 48h, zero after 48h.
  • In-Class Quizzes (20%): Five 20-minute paper-based, closed-book quizzes (Weeks 3, 5, 7, 9, 11) during the last 30 minutes of class. The lowest quiz score is dropped (best 4 of 5 count, 5% each). Quizzes cannot be made up. A quiz missed with an excused absence (absence form submitted at least 60 minutes before class) uses the drop; if a second quiz is missed with an excused absence, the quiz component is pro-rated over the quizzes you took. An unexcused missed quiz scores zero.
  • Final Individual Project (30%): Comprehensive reproducible public health analysis with Quarto report, 5-minute video walkthrough, and AI-use appendix. Released Week 10; due Dec 16 at 11:59 PM.

Extra Credit: Textbook Proofreading (up to +2%)

Our textbook, R Programming: Zero to Pro, is open source, and you can help improve it while you study. You may earn extra credit added directly to your final course grade:

  • +0.5% for each pull request to r02pro/r02pro_source that gets merged (typos, grammar, code fixes; use the edit button on any book page).
  • +0.25% for each issue the instructor labels accepted (confusing explanations, wrong output, suggestions you cannot fix yourself).
  • Capped at +2% total.

Rules: contributions count from Sep 2 through Dec 16, 2026 (11:59 PM ET); submit under the GitHub account you use for this course; search existing pull requests and issues first, since the first report wins and duplicates earn no credit; each pull request should cover one section; you must personally verify every problem you report (see the course AI policy). Read the contributing guide before your first submission. As a bonus, every contributor is permanently named in the book’s acknowledgments.

Statement on the Use of AI Technology

This course uses a Three-Zone AI Policy: - 🟢 Green Zone (Permitted with Citation): Weekly exercises, in-class practice, and final project development. You may consult LLMs (ChatGPT, Claude, GitHub Copilot) for code explanations, syntax queries, and debugging hints. All AI assistance must be acknowledged in an AI-Use Appendix. - 🟡 Yellow Zone (Guided / Supervised): In-class AI auditing activities where we evaluate AI-generated code quality and hallucinated arguments. - 🔴 Red Zone (Strictly Prohibited): In-class paper quizzes, uncredited code submission, or presenting AI-generated work as your own independent reasoning.

See the dedicated AI Policy Page for full guidelines and citation templates.
